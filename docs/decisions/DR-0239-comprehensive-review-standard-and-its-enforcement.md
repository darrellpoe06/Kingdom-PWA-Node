## Context

"Comprehensive" had no definition, so it meant whatever the reviewer thought to
trace. Three receipts in one week, three distinct miss classes: the 2026-07-27
messaging review FOUND both roster gaps and dated them for the 29th — Darrell
hit them live on the 28th (found-but-parked); the header wordmark collapse
survived every gate and multiple UI/UX passes because no instrument measured
rendered geometry (unmeasured dimension); a Gmail runbook shipped desktop
PowerShell to a ConnectBot-shell principal the house record already described
(recorded context unapplied). And the deeper failure Darrell named: encoded
processes have been LOST before — a document is read when consulted, and
context compaction erases what only memory carried.

## Decision

1. **The standard:** `docs/00-foundations/_root/COMPREHENSIVE-REVIEW-STANDARD.md`
   (Layer 3) defines a comprehensive review as SEVEN dimensions, each named
   from a real miss: (1) SHOULD/ARE spec-conformance (DR-0219); (2) JOURNEY
   WALKS (persona × entry × device, end-to-end as that user); (3) SURFACE-
   SAYS-TRUTH (every explanatory string checked against the traced mechanism —
   a false footer is a first-rank defect); (4) FORM-FACTOR SWEEP (chrome
   measured in a real browser at real widths); (5) DELIVERY-CONTEXT (his-hand
   steps matched to the recorded bench before handover); (6) FINDINGS ARE A
   WORK QUEUE (DR-0236 — dating a finding requires a named blocker);
   (7) GATE-THE-CLASS (every miss ends as a machine check or a pinned line).
   A skipped dimension carries a why + `re-review:` date, never silence.
2. **Enforcement is machinery, not memory — the answer to "what then":**
   (a) **Layer 0**: CLAUDE.md carries the standard's pointer, loaded first in
   every session, surviving compaction by construction; (b) **the stop-hook**:
   `ari-integrity-guard.js` gains `comprehensiveReviewConformance` — a reply
   that CLAIMS a comprehensive review while showing fewer than 4/7 dimensions
   is BLOCKED by the harness before it reaches Darrell (the same hook that
   already blocks re-asks; it fired on the agent's own reply earlier this same
   day — the mechanism is live, not theoretical); (c) **CI**:
   `scripts/chrome-layout-probe.mjs` runs on every push (selftest-break first —
   the probe must prove it CAN fail, then judge the real build); (d) **the
   review-watcher** (daily) already sweeps every dated skip this standard
   produces. None of these depend on any session remembering anything.
3. **The probe is the first new instrument the standard demanded:** dimension 4
   was unmeasurable until today — jsdom cannot do geometry. The probe serves
   the built dist the sw-nav-check way and asserts, in real Chromium at
   360/768/1440px: no page overflow, the brand reads horizontally, nothing
   overlaps the name. Proven-to-catch: the deliberate collapse trips 3/3
   (h1 at 14x312px — the exact letter-stack from the screenshot); the fixed
   build passes 3/3.
4. **Lost-process recovery is standing, not a one-off:** anything Darrell
   re-speaks that was lost is encoded + gated the SAME session (SPOKEN-
   TEACHINGS' covenant applied to process); the watcher's daily overdue scan
   is the structural recovery net for dated items already on record.
5. **NOT decided:** no new automation timers, no compute-spawning loops — the
   hook and probe are bounded, non-spawning checks in existing lanes.

## Consequences

- Every future "comprehensive review" response names the seven dimensions with
  results, or the harness blocks it. The standard improves under DR-0075:
  each new miss class adds its dimension AND its gate in the same session.
- **re-review: 2026-08-25** — first month of the standard: did the hook fire
  correctly (false-positive rate), did the probe catch anything, what classes
  were added?
