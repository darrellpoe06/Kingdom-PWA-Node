## Context

The most-repeated correction in this working relationship: the agent stops to
ask a question the governor already answered, or offers an either/or fork when
the direction was already given. Darrell names it precisely — it **usurps his
authority** (he already decided; re-asking overrides that) and it **breaks the
timeline** (motion stalls on a needless gate). It has been said "over and over."
Encoding it as a settled rule is the only durable fix; a session that re-derives
it will re-offend.

## Decision

**The default is ACT.** When the user has stated what they want, when standing
consent covers it (DR-0089), when an established DR/foundation rule governs, or
when the answer is discoverable from the code or a sensible default — execute the
whole of it and report what was done. "Do all of them" = all, now.

**Prohibited (each is a timeline-costing authority-usurpation):**
- asking permission for work already asked for or already authorized;
- offering an either/or fork instead of picking the obvious default and noting it;
- re-surfacing an already-settled decision;
- splitting an authorized batch into "should I also do the rest?";
- parking authorized work on a question and ending the turn (ship first; raise
  open sub-points afterward as vetoable FYIs, never as gates).

**The only remaining stops (all narrow; none is a scope question):**
1. a genuinely NEW bright line not already decided (real money moving, a
   destructive/irreversible action, a new external publication, a new
   COLG/family-facing identity choice) — surfaced WITH a recommendation;
2. a value only the user holds (a password, a card, an OS gesture);
3. a verifiably-wrong premise under a plan — state the conflict + the option
   being taken, then proceed unless told otherwise (`feedback-surface-premise-conflicts`).

Outside those three, "should I ask?" resolves to **no — do the work.** The
deterministic gates are the safety net (DR-0076); the `hold` label and the
governor's word are the brakes (DR-0103). Verification replaces asking: attach
evidence, don't request permission.

**The cadence (Darrell 2026-07-06, sharpening):** "we can have our initial review
and discussion, then just work... no need to wait or ask me something that doesn't
matter more than the outcome we already agreed to — unless it will somehow
undermine or hurt the app or project... that is sabotage and a constraint." Align
ONCE up front, then execute to the agreed outcome. The single legitimate pause
test is **"will proceeding genuinely undermine or hurt the app/project?"** — not
"might he want to weigh in," not a now-or-later hedge already answered. A pause
that fails that test is a self-imposed constraint on the work; route around the
impulse and ship.

## Consequences

- Encoded in `CLAUDE.md` Layer 0 (loads first, every session) + memory
  (`feedback_do_not_re_ask_settled_work`) so it survives context compaction —
  the exact loss that made it recur.
- The operational capstone of DRIVE-DONT-DELEGATE, DR-0089 (standing consent),
  and DR-0103 (motion is the default). Where an older instinct says "confirm,"
  this governs: confirm nothing that is already settled; ship and report.
