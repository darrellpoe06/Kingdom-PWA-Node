## Impact

A lesson no longer waits for a clock. The teaching reaches a writer the instant it is written, every version any writer produces is kept and gated the same way, and nothing ships that has not passed the verse gate. Darrell chooses between versions in the app, part by part, and his composite is gated again before it ships. With no writer reachable nothing changes: the hourly Routine keeps building.

## Decision

### The trigger — no polling interval
Migration 0240 adds `agent_inbox_lesson_notify`: a row tagged `lesson`, not `lesson-captured`, not `lesson-building`, inserted or with changed tags, calls `pg_notify('lesson_inbox', <id>)`. The Whisper loop's transcript insert IS the hand-off (the same database); a typed lesson and a Governor's approval ring the same way. `poetech-lesson-builder.service` LISTENs; it sweeps once at start, after a reconnect, and on SIGHUP (the installer sends one per services-sync cycle as the backstop for anything written while it was down).

### The stages, and the vocabulary "Your lessons" reads (DR-0668)
Each stage writes a tag `build:<stage>@<UTC ISO time>` on every row of the teaching:

`claimed` → `grouped` → `verses-fetched` → `writing` → `written` → `gated` → `selected` → `numbered` → `files-written` → `test-generated` → `reconciled` → `tested` → `committed` → `pushed` → `published`; the other roads: `failed`, `released`, `deferred`, `duplicate`, `skipped-test`, `awaiting-review`, `decided`.

Other tags: `lesson-building` (held while a build owns the row), `build-group:<build uuid>`, `build-mode:<mode>`, `build-prompt:<sha256 first 16>`, `build-writer:<name>`, `build-lesson:L<n>`, `build-dr:DR-<n>`, `build-decision:<decision uuid>`, `build-tests:ci-only`, `build-failed`, `build-reason:<text, 200 chars>`, `awaiting-review`. After the push SUCCEEDS, and only then: `lesson-captured`, `lesson-published`, `lesson-id:<id>` (the original voice row, `of:<id>`, gets `lesson-captured`). `lesson_builder.stage_times(tags)` is the reader.

Deterministic stages: eligibility (the Routine's own rules: owner rows, `lesson-approved` member rows, raw voice rows wait for their words, `voice-failed` and `canary` left to the Routine); one teaching, one lesson (a transcript and a typed copy grouped by 5-word shingles; a teaching whose longest sentences already stand in a catalog or record is tagged `parallel-compared`, built nothing); verses cited in the teaching fetched verbatim from `app/public/bible/kjv` into the prompt; lesson and DR numbers reserved under an exclusive file lock above `origin/main`, every branch pushed in the last 21 days and INDEX.md's own claims; the lesson object, its day, the weeks count, the pinned verse test (every span pinned, a one-word proven-to-catch), the six baselines and the learn-crosslist total, the DR and its INDEX row; branch `claude/lesson-l<n>-<slug>`, commit, `git push -u` (the lane opens the PR and merges on green).

### The writing stage — pluggable, identical prompt, every version kept
Writers are a list in NAS config (`/volume1/PoeTech/secrets/lesson-writers.json`), never in the repository; **no model identifier is committed** (a test fails if one appears in the builder's code). Adapters (`kind`), each skipped and reported "not configured" when nobody configured it:

| kind | family | enabled by |
| --- | --- | --- |
| `cli-local` (PRIMARY) | claude | the Claude Code CLI signed in on the NAS as `dpoe` (the installer installs it; Darrell signs in once) |
| `cli-ssh` | claude | `target` user@host + `key`, where the CLI is signed in (no key road exists today; see above) |
| `api` | claude | an Anthropic key on the NAS + `model` in config (optional) |
| `gemini-api` | gemini | a Gemini key on the NAS + `model` |
| `gemini-cli` | gemini | the Gemini CLI signed in on the NAS (or `target` over SSH) |
| `openai-api` | openai | an OpenAI key on the NAS + `model` |
| `codex-cli` | openai | the Codex CLI signed in on the NAS |
| `ollama` | ollama | `url` (the tower or the NAS) + `model` |
| `openai` | compat | any OpenAI-compatible `base_url` + `model` (+ key) — Grok, Mistral, DeepSeek, local servers |
| `command` | openclaw / compat | `argv` of any local program (prompt on stdin, reply on stdout): THE SEAM for OpenClaw on the tower (DR-0670), which may instead ship `<kind>_writer.py` exposing `WRITER` |

The prompt is built ONCE per teaching (the lesson standard of L193-L195 and this file's Layer 0 rules; the depth floors: lesson ≥ 2000 words, each band ≥ 1000, ≥ 40 referenced quotations, quiz 6, talking points 10, benefits 12), its sha256 taken, and the identical text sent to every writer in parallel. Each adapter reports the sha256 of what it put on the wire; a mismatch marks that version `prompt-mismatch` and it cannot ship. A second attempt at a failed teaching is told, deterministically, exactly which checks the first failed.

**Modes** (NAS config default `all-at-once`; the Governor's control `lesson_builder_settings.writer_mode`; one row may choose its own with `writer-mode:<mode>` and `writer:<name>` tags): `primary` (the primary writer only), `selected` (the primary plus the names ticked), `all-at-once` (every configured writer).

**Every version, the same gates** (Python, always; then the repository's own gate functions through `band_gates.mjs` when node is on the box, and the two verse scans must agree): verse (each referenced span in the verse it names, including `unresolvable` and `shouted`), quotation integrity (every double-quoted span carries its reference; no ellipsis, curly double quote, record id or percentage), our voice (no generic "God", no capitalised adversary name, no lowered holy name), structure and depth, full levels, reading level, band differentiation, title in narrative. Results, time and usage are stored per version.

**Which version ships.** `primary` mode, or only one draft: the primary writer's version if it passed every gate, else the best-gated passing version; never one whose verse gate failed. More than one draft (`selected` / `all-at-once`): **nothing auto-ships** — every version is stored, the teaching is tagged `awaiting-review`, and it waits for Darrell's decision.

### The decision stage
The app writes `public.lesson_decisions`; the insert rings `decision:<id>`. The builder claims it (`decided` → `building`, once), assembles the composite — the base `version_id`, then each `merge_map` part from its version, then `edits` — with **quoted Scripture locked** (an edit that changes, adds or drops a quoted span is refused, naming the part), re-runs EVERY gate on the composite, and either ships it through the same lane (recording `lesson_id`, `branch`, `pr_url`, `status = 'shipped'`, and a `lesson_versions` row for the composite with `published = true`) or writes `status = 'gate-failed'` with `gate_result.failures = [{check, part, detail}]` and ships nothing.

Parts a merge map may name: `title`, `slug`, `placement`, `bigIdea`, `inApp`, `anchor`, `benefits`, `levels.child`, `levels.youth`, `levels.teen`, `levels.senior`, `quiz`, `facilitator`, `lesson_intro`, `movements` (all) or `movements.<i>` (one; numbered by the builder, so a merge still reads 1, 2, 3), `lesson_close`, `dr_summary`. Edits may also name `movements.<i>.title` / `movements.<i>.text`.

### Backfill — compare, never replace
A backfill (requested in `lesson_builder_settings.backfill_requested_at`, scope `all` or a comma list of lesson ids; rings `backfill`) re-writes existing Living Lessons through the writers for comparison. Each prompt is rebuilt ONLY from the recorded source section (The report / Context / The source / What was sent / The teaching / What Darrell sent, 40 words or more) of the decision record that names the lesson; a lesson without one is skipped with the reason, never reconstructed. Backfill rows carry `backfill = true`, `source_ref`, the existing `lesson_id`, and `published = false` ALWAYS: the backfill path has no file write and no push, `Db.insert_version` refuses a published backfill row, and the table's `CHECK (NOT (backfill AND published))` refuses it again. No count cap; each lesson runs in its own budgeted process under its own lock.

### The tables (the shapes the "Your lessons" surface reads, DR-0668)
- **`public.lesson_versions`**: `id uuid`, `build_id uuid` (one build = one prompt), `teaching_row_id uuid` (null for backfill), `instance_id uuid`, `lesson_id text` (set when published; the existing id for backfill), `writer text` (config name), `family text` (claude / gemini / openai / ollama / openclaw / compat / merge), `model_label text` (from config), `prompt_sha256 text`, `prompt_text text`, `body jsonb` (the writer's object: verdict, placement, title, slug, bigIdea, inApp, anchor, benefits, levels, quiz, facilitator, lesson_intro, movements[{title,text}], lesson_close, dr_summary), `gate_results jsonb` (`passed`, `verse_passed`, `verse{spans,verbatim,faults}`, `quotation`, `voice`, `structure{counts}`, `depth`, `repo_gates{verse,quotation,fullLevels,readingLevel,differentiation,title}` or `{skipped}`), `elapsed_ms int`, `usage jsonb` (tokens / cost as the adapter reports), `error text`, `published bool`, `backfill bool`, `source_ref text`, `created_at`. Read: Darrell's two accounts and the Governor (`is_lesson_steward()`); write: the service role only.
- **`public.lesson_decisions`**: `id`, `build_id`, `teaching_row_id`, `instance_id`, `version_id` (take one), `merge_map jsonb {part: version id}`, `edits jsonb {part: text}`, `decided_by` (= `auth.uid()`), `decided_at`, `status` (`decided` → `building` → `shipped` | `gate-failed` | `failed`), `gate_result jsonb` (`passed`, `failures[{check, part, detail}]`, `gates`, `sources{part: version id | "edit"}`), `lesson_id`, `branch`, `pr_url`, `processed_at`. A steward INSERTS a new decision, born `decided` with no outcome; the builder writes the outcome.
- **`public.lesson_builder_settings`** (one row, `id = 1`): `writer_mode`, `selected_writers text[]`, `backfill_requested_at`, `backfill_scope`, `backfill_done_at`, `backfill_summary jsonb`, `service_status jsonb` (every writer tried: `writer`, `kind`, `family`, `primary`, `ok`, `why`, `configured`; `state`: `ready` | `waiting on a writer` | `waiting on a push credential` | `stopped`), `service_status_at`, `updated_by`, `updated_at`. A steward may update ONLY the control columns (column grants); the service writes its status.

### The brakes (the amended law: DR-0247, DR-0248, DR-0667)
- **No count cap.** Every waiting teaching starts (proven with 25 at once).
- **Budget.** Each build, decision and backfill runs in its own process group under `LESSON_BUILD_MAX_SECONDS` (default 2700); on overrun the whole group is killed and the rows are marked `build:failed` with `build-reason:budget ...` — never left looking busy.
- **Lock.** Per row, twice: an `O_EXCL` lock file (broken only when its process is gone or older than the budget) and the atomic database claim (`lesson-building`, set only WHERE the row does not already carry it). Decisions are claimed `decided → building` once.
- **Kill.** The stop-paths of the deterministic fleet, checked before every job: `services.json` `lesson-builder` `enabled: false`, or `infra/nas-loops/ARMED-BY-RECORD` removed. A stopped service claims nothing and says why.
- **Retries** are bounded by `LESSON_BUILD_MAX_ATTEMPTS` (2); after that the teaching is left for the hourly Routine.

### Dormant until a writer
With no writer reachable, or no push credential, the service claims nothing and publishes its state (`waiting on a writer`, each writer and why) to `status.json` and `lesson_builder_settings.service_status`; the hourly Routine remains the builder. This builder writes **Living Lessons**; a teaching whose writers place it in another course is tagged `deferred` and left to the Routine (re-review below).

## Verification

- `python3 -m unittest test_lesson_builder` — **72 tests, all passing on Python 3.11 and on Python 3.8** (the NAS's version), gating merge in `ci.yml`. Proven-to-catch: a one-word verse change fails the build; a merged part with a one-word drift fails on THAT part; an edit touching quoted Scripture is refused; a writer that alters the prompt is caught; primary mode never runs a second writer; more than one version never auto-ships; a verse-failed version never ships even as primary; a failed push never marks the row; the budget ends a hung build (30 s sleep, 1 s budget) and marks its rows failed; the row lock refuses a second holder and the same row is never built twice; a claim whose build is gone is released on the sweep and a live one is not; each stop-path stops it; a published backfill is refused; a thin draft fails the depth floors. Parity: the repository's own gates and the Python gates agree on L195's spans.
- The 0240 migration applied twice (idempotent) and its smoke passed on Postgres 16; the smoke failed on each broken policy. It runs for real in `rls-isolation.yml`.
- Guards: tenancy-guard PASS (the overlay covers the two new instance-scoped tables), rls-isolation matrix guard PASS, business-systems-guard OK, services-sync guard and the flow graph carry `lesson-builder`.
- **After merge, measured, not assumed:** the next services-sync cycle's log names the builder's state and each writer's reason; `status.json` / `service_status` read `waiting on a writer` until the sign-in, then `ready`; the first spoken lesson after that carries `build:*` tags seconds after its transcript row.
- **Needs the Routine to know the builder** (one line in its stored prompt, Darrell's session owns it): skip rows tagged `lesson-building` or `awaiting-review`, so the hourly fallback never races a live NAS build or pre-empts Darrell's review.
