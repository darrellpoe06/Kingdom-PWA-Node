# DR-1431: The lesson lane reads its own queue without the runner's key — the census the NAS already took is turned outward, and a green run must mean the queue was read

**Date:** 2026-11-12
**Status:** Accepted
**Tier:** A (one new read-only receipt function and its reader; a second road added to an existing dispatch-only lane; no schema, no door, no money)
**Type:** ways + lane
**Area:** the lesson intake lane; the sovereign database's public receipts
**Found by:** the hourly voice-lane tick, reading its own run log — not asked for
**Pairs with:** DR-1360 (the NAS initiates every road; a credential that expires is never again the only road to a value the house holds), DR-1399 + migration 0318 (the house says how its clock ran — the shape reused here), DR-1269 (two roads to a public value, NAS first), DR-1186 (an unreadable queue reads UNKNOWN, never zero), DR-0725 (one definition of "waiting"), DR-1284 (the join step is not a witness of the join), DR-0621 (hold the hand of the process — work it until it works, never rebuild beside it), DR-0076 §3 (proven-to-catch), DR-0108 / DR-1159 (review our Ways; the order of roads to a NAS value)

## Context

**What was measured, and what I had been doing about it.** `inbox-lessons-waiting.yml` is the FIRST step of Darrell's hourly lesson intake — the PRIORITY lane. Runs **#500, #501, #502, #503, #504 and #505** all ended at the same step, `Join the tailnet`, because the runner's Tailscale key expired on 2026-11-04 and again by 2026-11-10. Six consecutive firings of the lane that carries his own teachings could not read a queue that was sitting on a machine that was up the whole time.

On each of those ticks I dispatched the probe again, read the same failure, reported the same remedy — a fresh Reusable + Ephemeral `TS_AUTHKEY`, a value only Darrell can mint — and ended the tick. That is six ticks spent re-measuring a known failure and waiting on a hand. **The waiting was the defect, not the key.** DR-0108 says a stated "can't" is an unverified premise to challenge, and DR-1360 had already decided the direction: *"a runner road that carries work INTO the NAS is retired as each is reversed"*, and *"a credential that expires is never again the only road to a value the house holds."* This lane was still the un-reversed one.

**The write half already existed, and was already enabled.** `infra/nas-loops/lesson-queue-census.py` — registered `enabled: true` in `infra/nas-loops/services.json` — counts the waiting rows on the NAS itself every services-sync cycle and patches ONE row into `agent_inbox` tagged `lesson-queue-census`, source `nas-loops`: totals by road and by shape, the oldest wait, and the exclusion list it used. Its own registry entry ends: *"NOT YET PROVEN (P66): it counts as working only when a stamp from it is read, and the session that wrote it could not watch it run — the only road from the cloud to this machine is the expired key that caused the problem."*

So the house was already counting its own queue, and nothing outside the house could read the answer, **because the only road out was the same dead key the census existed to survive.** A witness nobody can read is not yet a witness. The missing piece was never the key. It was the read.

## What was measured

- Runs #500–#505 of `inbox-lessons-waiting.yml`: all `failure`, all at step 3 of 7 (`Join the tailnet`), steps 4–6 `skipped`. Run #505's job 130847419637 is the one read in full.
- `scripts/live-sql.sh`: the lane's only road is tailnet → ssh → `docker exec psql`, gated on `NAS_SSH_KEY` and a joined tailnet. No second road existed.
- The public road, by contrast, was already proven twice for other values: `scripts/served-anon-key.py` recovers the anon key from the served bundle (DR-1269), and `scripts/served-heartbeat-receipt.py` already reads `public.nas_heartbeat_receipt()` over `poetech.us/sb` **from a GitHub runner with no tailnet at all** (DR-1399, migration 0318).

## Impact

**What this obligates, and what it costs.** The queue is now answerable from outside the house over a road nobody has to mint a credential for, so "the queue could not be read" stops being an acceptable end to an intake tick — six ticks spent re-measuring one failure is the thing this record exists to make unrepeatable. The cost is accepted deliberately: `lesson_queue_receipt()` is callable by `anon`, and that key is public by nature, so this is a public endpoint stating how many teachings wait and their ages, roads and shapes. It is strictly narrower than the road it replaces — `inbox-lessons-waiting.yml` already prints `id / created_at / created_by / source / tags / body length` per row into a public run log and its rolling issue, while the receipt drops `created_by`, every id and the host name. Widening it later to a row id, a person, or a word of a teaching would cross a line this record draws rather than extend one.

**What now depends on it, and what is NOT changed.** The census stops being unproven the moment this read answers (P66), and the lane's green stops meaning "the job finished" and starts meaning "the queue was read" — the amended gate (Decision 6) changes the fleet's definition of a verified intake lane with it: a door may be passed on a shut road only while something downstream still fails the run on an unread queue. The `TS_AUTHKEY` is still dead, the three other intake lanes still ride it, and only the NAS road names individual rows, so the builder still needs it. This removes a single point of failure from *knowing whether work waits*; it retires no tailnet road, and the remaining three reversals are not done.

## Decision

1. **Migration 0320 turns the census outward.** `public.lesson_queue_receipt()` — `STABLE SECURITY DEFINER`, `search_path = public`, `REVOKE ALL FROM PUBLIC`, `GRANT EXECUTE TO anon, authenticated` — returns `{seen, at, total, oldest_waiting, by_road, by_shape, excludes}` from the newest row tagged `lesson-queue-census` **and** source `nas-loops`. It is 0318's proven shape pointed at a different row, not a new road (DR-0621).

   **What it will not carry.** Never a body — and this matters more here than for the heartbeat, because this function reads the table that holds every teaching. Never a row id, never a `created_by`, never the host name. `by_road` and `by_shape` keys are matched against the fixed lists the repository already publishes in `lesson-queue-census.py` (`ROADS`, `shape_of`), the way 0318 matched service names against the registry, so a key invented anywhere upstream cannot ride out. The result is **strictly less** than `inbox-lessons-waiting.yml` already prints into a public repository's run log, which lists `created_by` per row: this narrows the exposure it replaces rather than widening it.

2. **A count out of range goes MISSING, never to zero.** Measured on this migration's own proof run: the first shape clamped into `[0, 100000]`, and a corrupt body carrying `total: -5` read back as **`total: 0`** — a manufactured "nothing is waiting" from a row that said nothing of the kind, which is the single lie this whole lane exists to prevent (DR-1186). The clamp is gone; an impossible number is omitted and the reader says UNKNOWN. The gate that found this was my own adversarial seeding, not a review.

3. **`scripts/served-lesson-queue.py` asks it, and refuses in five distinct ways.** Every refusal is its own exit code, its own sentence, and `count=unknown` — never `0`: unasked (10), unreachable or refused (11), never counted (12), no usable total (13), **too stale to be current (14)**. The staleness line is the one that is easy to get wrong: the NAS clock is 15 minutes, so past four cycles the loop is not running, and a number from then is not an answer about now. It is reported as unknown **with its age**, not as today's queue. A genuinely empty queue still reads `0` with exit 0 — the distinction the whole file turns on.

4. **The lane keeps both roads, NAS first.** The join is `continue-on-error` and the NAS read falls through to the served census. The NAS is asked first because only it can name the individual rows; the census can only repeat the count the house last took. This is the same two-road shape, in the same order, that DR-1269 proved for the deploy's anon key, and it is the same legitimate exemption from DR-1284's verify-your-join rule the Pages deploy carries: a step that may fail and **has** another road must not end the job. The join is still verified and a dead key is still filed on the fleet's rolling entry — the outage is never silent; only the consequence changed.

5. **A green run must mean the queue was read.** Both read steps are now `continue-on-error`, which is precisely how a lane starts reporting success for work it did not do. A closing step ties the job's conclusion to the one fact that matters — did either road produce a count — and fails the run when neither did. Without it this change would have manufactured a green lane with "UNKNOWN" in its own log: the gate-that-always-passes this house has paid for before.

6. **One standing gate is AMENDED, and the amendment is narrow.** `a-tailnet-join-is-not-a-witness.test.js` required every lane in `INTAKE_LANES` — the four carrying Darrell's spoken and in-app lessons — to have a verify step that `exit 1`s. That rule was written when dying at the door was the only honest answer an intake lane had to a shut road, and runs #500–#505 are what it costs now that there is another road: six firings that read nothing while the queue sat on a machine that was up.

   What the rule protects is not the exit code; it is that **a shut road on a lane carrying his teachings is never silent.** So the requirement is now stated as that: the run must fail when the queue was not read. A lane with no second road still fails at the door; a lane with one must fail at a closing step that reads BOTH roads' outcomes and exits 1 when neither answered. Neither branch can go green on an unread queue, which is the whole of it. This lane is also the first member of `INTAKE_LANES` to enter the second-road exempt set, named there with its reason as DR-1286, DR-1398 and DR-1399 named theirs — the list names lanes rather than counting them precisely so a lane joining it shows up in a diff.

## Verification

- **Migration 0320 was EXECUTED, not read.** A throwaway PostgreSQL 16 cluster, a minimal `agent_inbox`, the migration applied clean (its own `DO` self-check passed), then eight cases: (1) no census row → `{"seen": false}`; (2) the real body **generated by `lesson-queue-census.py` itself** → the full correct receipt; (3) a real lesson row holding `SECRET-TEACHING-WORDS-MUST-NEVER-LEAVE` seeded beside it → absent from the receipt, along with any uuid and the host name; (4) an invented `evil-injected-road` key dropped, `total: -5` and `by_shape: 900000` omitted rather than clamped; (5) a non-JSON body → `seen` + `at` only, no invented counts; (6) the right tag with a **wrong source** → `{"seen": false}`, so a member's lookalike cannot speak for the house; (7) `SET ROLE anon` → the function executes; (8) `SET ROLE anon` → `permission denied for table agent_inbox`. Case 4 is what caught decision 2 above.
- **The reader was run over real HTTP**, against a local server returning each receipt shape: exit 0 with `read=ok count=3` and the right `GITHUB_OUTPUT`; exit 11 on a 404 naming migration 0320 (what a runner sees until this merges); exit 10 with no key; and 12/13/14 on their own receipts. In every refusal `count` is `unknown`.
- **12 cases** in `app/src/__tests__/the-queue-is-readable-without-the-key.test.js`, **proven to catch five ways**: removing `continue-on-error` from the join, deleting the closing gate, letting the host name ride out, restoring the clamp, and dropping the source check — each broke the case written for it, and the files were restored and re-proven clean afterwards.
- **Three standing gates caught this change and were answered rather than relaxed**, which is the part worth reading. `a-tailnet-join-is-not-a-witness` caught the verify step no longer exiting 1 AND the lane silently joining the second-road exempt set; `the-waiting-queue-has-a-witness` caught a reworded UNKNOWN line it pins by phrase, and the phrase was restored in the workflow rather than loosened in the gate. The amended rule is **proven to catch on BOTH branches**: deleting this lane's closing gate fails it by name (`has a second road but no closing step that fails an unread queue`), and turning `lesson-inbox-bell.yml`'s door `exit 1` into `exit 0` fails it by name too (`no second road, so the verify step must fail the run at the door`). Restored and re-proven green after each.
- Lint clean (eslint, ruff); `grant-guard`, `constraint-allow-list-guard` and `record-length-guard` green.
- **Honest limits.** The live end-to-end read cannot be taken from this sandbox, which has no route to `poetech.us` (DR-0125): until migration 0320 is applied by the NAS's own `sovereign-replay` loop, the served step exits 11 saying exactly that, and the lane keeps failing honestly rather than quietly. Merging is the deploy — the NAS pulls the mirror and the replay loop applies the file on its own clock — so the first dispatch after that is the proof, and it is the same first-run proof P66 asks of the census itself. **The census remains unproven until that read returns a stamp**, and that read is now possible for the first time, which is the point of this record. The `TS_AUTHKEY` is still dead and still worth replacing: the NAS road names the individual rows and the census only counts them, so the fuller answer still wants the key. What no longer waits on it is knowing whether a teaching is waiting at all.
