## Context

The church's own video of a class is the second witness for a church lesson (DR-0333 pass two, DR-0712). L202, the 2026-09-30 class, needs that video's transcript. The road is the NAS: `corpus-reconcile` lists the channel into `choir_sermons`, the **transcript-trickle** rider fetches captions into `video_transcripts` from the NAS's residential IP, and the **choir-dates** rider dates undated rows with yt-dlp. `church-video-witness.yml` reads what the road wrote.

On 2026-10-01 every services-sync fire that day reported both riders DEGRADED.

The trickle line appears every twelfth call: the 3 h stamp gate was working; each fire ended the same way.

But its end-of-run report computed `gaps = total - with_text`, counting the 120 verdicts as owed, and its stall guard fired on `attempted == 0 and gaps > 0`. **Root cause of the trickle's DEGRADED: a counting bug in `load-transcripts.py`, not credentials, not a block, not yt-dlp.** The trickle does not use yt-dlp (it uses `youtube-transcript-api`, vendored and importable since 2026-08-11). `harvest-health.yml` had already fixed the same count on its side (`owed = total - transcribed - verdicts`); the loader never was.

## Impact

Two riders read DEGRADED all day, so a reader of the fleet saw a stalled road where one rider was done and the other had no tool. The real reason the 2026-09-30 class had no second witness yet (the channel listing had not run since Monday) was hidden behind both.

## Decision

1. **Owed means no text and no verdict.** `load-transcripts.py` counts coverage with `coverage(state, worklist)` → (transcribed, answered with no captions, owed), the same rule as `harvest-health.yml`. The end of each run is one of four outcomes (`run_outcome`): `ok` (work done), `blocked` (every attempt refused; backoff as before, exit 3), `stall` (nothing attempted while videos are still owed; exit 3, a real fault), `drained` (nothing owed; exit 0, says so). The report reads `Coverage: 756/876 videos transcribed; 120 have no captions (answered, Whisper's queue); 0 still owe a caption fetch.`
2. **The NAS installs its own yt-dlp** (`infra/nas-yt-dlp/install.sh`): the pinned standalone build into `/volume1/PoeTech/yt-dlp`, verified against the committed SHA-256 (a mismatch is deleted and never run) and against `--version`; a wrapper keeps its unpack directory on the volume. Idempotent: a matching recipe and an answering `--version` make every later cycle one process start. A failed download is retried at most every 6 h. Moving the pin is a one-line PR.
3. **choir-dates uses it first.** `choir_dates_install.sh` runs the installer each cycle and puts `/volume1/PoeTech/yt-dlp` first on PATH; the docker wrapper is entered only when the sovereign build is not ready. `choir_dates_sync.py` asks for metadata with `--ignore-no-formats-error` (it never wants a format, only the stamp), and names its failure: "not available" only when no yt-dlp could start; "ran but printed nothing" with yt-dlp's own last words otherwise.
4. **The witness reads the road.** `voice-intake-health.yml` gains a read-only step: the trickle's own last lines, its state files, the installed yt-dlp recipe and `--version`, the docker the old wrapper needs, the box's glibc, and choir-dates' last words. It never touches YouTube.
5. **Armed by record (DR-0247, DR-0248).** No new service, clock or switch: both riders already ride services-sync, whose lock and timeout stand; the installer's own brakes are the 6 h retry and the checksum. Stop-path: `enabled: false` on choir-dates in `services.json`.
6. **Not in this change, named:** the 120 videos with no captions are Whisper's queue (DR-0611's ladder: the tower's Whisper, then the NAS CPU). That road needs the audio, which the NAS's own yt-dlp now makes possible; building it is its own change. `re-review: 2026-10-08`. The channel listing still runs on a GitHub runner twice a week (`corpus-reconcile.yml`, which DR-0333 predates); moving it to the NAS with this yt-dlp is the sovereign follow-up, `re-review: 2026-10-08`.
