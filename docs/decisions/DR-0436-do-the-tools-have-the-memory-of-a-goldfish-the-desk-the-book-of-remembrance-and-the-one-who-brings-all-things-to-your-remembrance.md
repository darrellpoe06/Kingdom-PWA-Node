## The report

Darrell forwarded **ByteByteGo** of 2026-09-15 (blog.bytebytego.com), *"Do LLMs Have the Memory of a Goldfish?"*, with the single word **"Lesson."** The article's claim: the model has no personal or persistent memory of previous interactions; what looks like memory is the **application** around the model storing messages, keeping summaries, retrieving memories, maintaining a profile, and placing some of that in front of the model each call — reconstructed memory, not recollection. It separates three things called memory: trained memory (the weights), working memory (the context window — a desk, not a mind; cleared when the call ends), and persistent application memory (a database, file, vector store, or profile service outside the model). It walks a basic stateless call (a name given in one request is not available in the next unless resent), notes that some providers offer server-managed conversation state without the model itself developing memory, frames the context window as a token budget with a hypothetical 100K split, names context rot, shows why long conversations grow expensive and why prompt caching is an optimization rather than a memory architecture, describes what happens when the window fills (reject, drop oldest, rolling window, summarize, server-side compaction), and surveys the techniques: sliding windows, conversation summarization (lossy — a summary is an interpretation; summarizing summaries drifts like copying a photocopy; store important facts separately), structured entity extraction, vector-store retrieval (selects what deserves space; needs metadata), and long-term profiles (stable preferences, with timestamps, sources, confidence, and updating). Its conclusion: what appears to be memory is a carefully constructed system of context reconstruction, summarization, retrieval, and persistent storage; the surrounding architecture matters at least as much as the model.

## DR-0100 tiers applied (verified by live web search and provider documentation, 2026-09-15)

- **Tier 1 — documented, stated plainly, source and date named.** The article's mechanism matches current provider documentation, read directly 2026-09-15: a frontier provider's Messages guide states verbatim, *"The Messages API is stateless, which means that you always send the full conversational history to the API."*; its Context windows page defines the window as the working memory for the model, distinct from the training corpus, states that everything in the request (system prompt, messages, tool results, tool definitions, output) counts toward it, and states verbatim, *"Cached prompt prefixes still occupy the context window: prompt caching changes what you pay for those tokens, not whether they count."*; the same page states *"As token count grows, accuracy and recall degrade"* and names the phenomenon *context rot* — the term Chroma's 2025 research (trychroma.com/research/context-rot) used after testing eighteen models; its Compaction page documents server-side compaction under a beta header dated 2026-01-12 that replaces older content with a concise summary in a compaction block when a token threshold is crossed. OpenAI's *Conversation state* guide (developers.openai.com/api/docs/guides/conversation-state) is a second witness for stateless requests with optional server-managed state, as summarized in search results (page egress-blocked for direct fetch).
- **Tier 2 — genuinely open, flagged narrowly.** How much a given summary loses in a given case is not a fixed number (the article rightly says a detail that seemed unimportant may matter later). Whether ever-larger windows will one day make external memory unnecessary is a forecast, not a fact; the documented trend today is degradation as the desk fills.
- **Tier 3 — over-reach the Word corrects while the data stands.** The felt claim that the assistant *knows me*. It reconstructs a context; it does not know a soul: "thou understandest my thought afar off" (Psalms 139:2); "there is not a word in my tongue, but, lo, O LORD, thou knowest it altogether" (Psalms 139:4). ## The Word settles what the debate cannot

The anchor is the One who does not forget — "Can a woman forget her sucking child, that she should not have compassion on the son of her womb? yea, they may forget, yet will I not forget thee. Behold, I have graven thee upon the palms of my hands; thy walls are continually before me." The article's sharpest engineering rule — never trust the narrative summary, store the exact fact — is the Word's rule about itself: "the scripture cannot be broken" (John 10:35); "one jot or one tittle shall in no wise pass" (Matthew 5:18); the tradition of men is a summary of a summary (Mark 7:13). The fruit: a learner leaves able to say plainly what a tool keeps and what it cannot, to keep the household's covenant in writing (with dates, names, and sources) and in the Spirit rather than in the tool, and to open the Scripture Library and the Build board and see the house doing exactly that.
