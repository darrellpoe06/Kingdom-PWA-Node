## Context

`ensureBase` was built this morning so `format-guard` could resolve its own merge base in a depth-1 CI checkout (DR-1350). It opened with `if (has()) return true` — if a merge base already exists, fetch nothing.

## What was measured

**A present base can be stale, and the guard then reports OK over nothing.** `base...HEAD` from a worktree whose `origin/main` is behind yields NO added files, so prettier formats an empty set and the guard prints a green line.

**Measured end to end on #2571**, which is the only place it could be: this worktree printed `format-guard: OK — 0 added JavaScript file(s)` and CI printed `1 finding(s) … (2 js)`. One `git fetch origin main` in the same worktree reproduced the CI failure exactly, naming `a-forward-safe-case-may-not-name-the-number.test.js`. The file was genuinely unformatted; the local pass was over an empty set.

**And a case of mine pinned the wrong premise.** `fetches nothing at all when a merge base is already there` asserted `fetch` was never called, with the reason written in it: *"a guard that fetches every run is a new cost on every job."* The cost is real and it was weighed against the wrong thing. **Measured rather than asserted:** the single-branch depth-1 refresh runs in **776, 808 and 965 ms** on three consecutive tries, against a `lint + guards` job that runs for minutes.

## Impact

Third door into one shape in one day: DR-1247 the stale tree, DR-1249 the unreadable base, DR-1359 the stale remote-tracking view — and now the stale base ref inside the guard written for door two. Every one is a read that was not actually made, reported as a clean result.

## Decision

**1. The base is refreshed first, every run.** One `--depth=1` single-branch fetch precedes the merge-base question. The expensive paths are unchanged and still fire only when the base is genuinely missing: the three deepen rounds, then `--unshallow`.

**2. A failed refresh does not stop the answer.** Offline, the fetch fails, `quiet` swallows it, and a merge base that was already there still resolves — so the guard still runs. It asked, which is the part that was missing.

**3. Two cases are corrected, not deleted**, with the measurement written into them, because the premise they recorded is mine and the record of being wrong is worth more than a clean-looking suite.

**Proven to catch.** Restoring the `if (has()) return true` short-circuit turns **4 cases red**, including one that asserts the refresh precedes the merge-base question for both a present and an absent base. File restored and verified byte-identical with `cmp`. Lint clean.

**Not claimed:** that the guard now sees every unformatted file. It sees the files added since a base it has just refreshed. A file changed rather than added is outside what this guard has ever covered, and `re-review: 2026-12-06` asks whether that is still the right scope.
