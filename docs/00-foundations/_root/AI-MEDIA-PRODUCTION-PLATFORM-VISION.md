## The vision in plain terms

A media production platform built on the same principles as PoeTech Family OS:

- **Sovereign** — runs on the family's own infrastructure (Synology NAS + future GPU box), not on Adobe Cloud or Runway or Pictory or any extractive SaaS.
- **Open-source where possible** — Stable Diffusion / FLUX for image gen, ComfyUI for workflow assembly, Whisper for STT, audio diffusion models for voiceover, open-source video editors that scriptable.
- **Family-first** — Christian's tech apprenticeship includes media production skills; Christyn's interests get supported; Christiana's bilingual capability becomes content infrastructure; Christina's clinical wisdom shapes how stories are told about real human experiences.
- **Theologically grounded** — Kingdom of Yahweh orientation. Content serves the King. Typographic theology binding applies to all generated text content (Yahweh / Jesus / Holy Spirit capitalized; lucifer / adversary never).
- **Perpetual** — the system gets better over time as the family uses it and feeds it back. Not a tool you finish; a tool you live with.

## Architectural pillars

### Pillar 1 — Sovereign generation

All generation runs on family-owned infrastructure where possible:

- **Image generation** — Stable Diffusion XL or FLUX on the future GPU box. Trained models stay local.
- **Video generation** — Stable Video Diffusion or similar open-source video models on the GPU box.
- **Voice / audio generation** — open-source TTS like Coqui XTTS for narration. Optionally voice-cloning of family members WITH EXPLICIT CONSENT for use in their own content.
- **Music** — open-source music generation tools (suno-like local options as they mature).
- **Scripting + storyboarding** — Claude or Gemini cloud for non-clinical scripts; Ollama for any clinical-adjacent content per TLC firewall.
- **Editing + compositing** — open-source ComfyUI / DaVinci Resolve (free tier) / shotcut / kdenlive automation.

Cloud generation tools used only for content where sovereignty isn't required and the cost/quality math wins.

### Pillar 2 — Family-curated content library

Every produced piece has clear provenance:

- Who initiated it (which family member's voice or which workflow trigger)
- What family-memory threads it draws from (per the family video archive)
- What principles + scriptures it grounds in
- Who reviewed it before publish (Quality Gatekeeper + Governor)
- Where it's published + how the audience can engage back

Becomes a real library, not a content dump.

### Pillar 3 — Theological review pipeline

Every theological-adjacent piece passes through:

- **Foundation-screen** — does this content respect THE-WAY, MIND-OF-CHRIST, EXCELLENCE-STANDARD?
- **Scripture-citation discipline** — every verse quoted follows SCRIPTURE-REFERENCE-STANDARD. No paraphrase without explicit "this is a paraphrase" tag.
- **Religion AND relationship balance** — does the content have backbone (scripture-grounded) AND warmth (meets the audience where they are)?
- **Typographic theology** — Yahweh/Jesus/Holy Spirit/Father/Son always capitalized; lucifer/satan/devil/adversary never.
- **Worldview alignment** — per THE-HOLY-SPIRIT-INTEGRATION-WORLDVIEW (the source of answers), the content reflects the worldview being lived, not improvised theology from training data.

Christina has weighted authority on pastoral / clinical content. Darrell has weighted authority on theological framing. The Quality Gatekeeper (Role 10) enforces the discipline; the Governor + co-Governor pair approves the publish.

### Pillar 4 — Distribution sovereignty

Where the content lives + how it reaches audiences:

- **Primary canonical home** — own infrastructure (NAS-served media; PoeTech video player on poetech.us).
- **Mirrors** — YouTube / Vimeo / podcast platforms as mirrors, NEVER primary. The family controls the canonical.
- **Embed-on-third-party** with attribution + canonical link back.
- **No platform-locked content** — every published piece is re-mirrorable; if YouTube changes its policy or disappears, the work persists.
- **Eventually:** federated distribution (Mastodon / PeerTube / similar open protocols) for reach without dependency.

### Pillar 5 — Audience consent + interaction

Distinct from "engagement metrics":

- Audience consent for any data captured (signups, comments, sharing).
- Per BUSINESS-PROCESS-CONNECTIONS: every viewer-facing surface answers the five questions before it ships.
- Comments + responses are MODERATED — by the family, not by community-self-policing. Foundation Agent assists triage; Governor + co-Governor decide.
- Replies to audience messages happen through the existing family-feedback workflows (workflow 30 extended).
- No engagement-bait, no manipulation, no dark patterns. The platform exists to serve, not to capture.

### Pillar 6 — Perpetual improvement

Per the same principles as the rest of PoeTech:

- Daily review cadence for shipping cadence + quality (workflows 31 + 32 extended).
- Quality Gatekeeper (Role 10) gates every publish.
- Tests for the production pipelines (Role 8 + Role 9).
- Family feedback (workflow 30 + Suggest button extended to the media platform).
- Storage + cost discipline — produced content stays managed, not infinite-grow.

## The "moving producing platform" technical stack (suggested, post-MVP)

For when the GPU box ships + the foundation is ready:

- **Hardware** — GPU box: 2x RTX 5090 or equivalent, 64-128 GB RAM, ~$3-5K one-time. Rack-mounted near the DS1621xs.
- **Image generation** — Stable Diffusion 3.5 Large + FLUX Pro on the GPU box. ComfyUI as the orchestration layer.
- **Video generation** — Stable Video Diffusion + future open video models. Modal-style local farm.
- **Audio** — Coqui XTTS + audiocraft + open-source music gen.
- **Editing automation** — Python + ffmpeg + DaVinci Resolve scripting + n8n workflows orchestrating it all.
- **Asset library** — Synology Drive + Postgres index of every generated asset with full provenance.
- **Publishing pipeline** — n8n workflows that take an approved final asset, push to canonical home + mirrors per a publish-plan JSON.

Estimated all-in capex: $5-10K spread over 12-24 months for the GPU + storage upgrades. Recurring: $50-100/month for power + minor cloud burst capacity. Comparable SaaS stack would cost $300-500/month perpetually with worse sovereignty.

## Risks + mitigations

**Risk: scope creep into the media platform before the core stewardship system is solid.** Mitigation: Governor (Darrell) explicitly gates phase transitions. Media work doesn't get LLM/GPU/dev resources until the core system meets its Phase 1-4 milestones.

**Risk: theological content drift if generation tools start producing improvised theology.** Mitigation: SCRIPTURE-REFERENCE-STANDARD enforcement is non-negotiable. Foundation Agent + Quality Gatekeeper screen every theological piece. Christina + Darrell co-sign theological work before publish.

**Risk: AI-generated content sounds AI-generated.** Mitigation: don't fight the medium — use AI generation for backgrounds, b-roll, scaffolding, NOT for the front-facing voice of the family. The family's actual voice and face is the primary content; AI is the production tool, not the speaker.

**Risk: storage + processing overwhelms the NAS.** Mitigation: storage budget per phase. Generated assets get auto-pruned after publish unless tagged "archive." GPU box added when sustained generation load justifies.

**Risk: extractive engagement patterns creeping in.** Mitigation: the audience consent + interaction pillar is binding. Comments moderated by family. No dark patterns. No data harvesting. Each surface passes the five-question test.

**Risk: producing content that lifts up ourselves instead of the King.** Mitigation: the senior question on every piece — does this lift up the King? Christina + Darrell co-review on substantive theological content. The platform serves a purpose larger than the family that built it.
