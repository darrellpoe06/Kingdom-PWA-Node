# PM-METHOD — Current State → Future State → Gaps → Decisions → Timelines (the seed)

**What this is.** The project-management discipline Darrell runs professionally (Shay's build; the IL Union project at UIUC), captured 2026-07-10 as a reusable seed (DR-0154). PoeTech is worked example #1; every future project (a business door, a church build, a client engagement) plants the same seed with its own sources. Ari carries this as a standing duty inside the PoeTech App.

**The posture.** The Governor governs; the PM engine executes and advises (GOVERNANCE-EXECUTION-ADVISORY). Every stage is bound to a LIVE source — a stage that cannot cite its source is not run, it is invented (NO-STATIC-DATA; VERIFICATION-DOCTRINE).

## The loop

1. **CURRENT STATE — derived, never described.**
   Roll up what the project's own record already says it is. For PoeTech: the decision ledger, review registry, incident ledger, boards/timelines, error journal, test census, and the outside-in health verdicts. For any other project: whatever its real record is — contracts, tickets, measurements. If the project has no record, building the record IS the first gap.

2. **FUTURE STATE — the governed intake.**
   What has actually been asked for, with sources: feedback and promote queues, the principal's directives, open opportunities with `re-review:` dates, and the commitments the project's own foundations/Ways already made. Scope is cited, never imagined.

3. **GAPS — the measured delta.**
   Future-State items with no shipped/verified counterpart: opportunities past their date, feedback beyond queue-freshness, incidents without structural closes, directives without decisions. Each gap carries its evidence line. A gap without a source is an opinion.

4. **DECISIONS — every accepted gap gets a record.**
   One decision per record (DR discipline), tiered for risk, carrying its why. Declined gaps get a why + re-review date (PERPETUAL-IMPROVEMENT) — never a silent drop.

5. **TIMELINES — every decision gets a lane.**
   A board item with an owner and a real date; phases whose completion writes its own record (the finish ripple). The delivery lanes implement; deterministic gates verify; the merge deploys; the live review confirms as a user meets it.

6. **MANAGE — the loop reports itself where the family lives.**
   Derived readouts stay current by construction; judgment calls surface as recommendations with defaults, never silent re-scoping. Any timer-driven cadence ships inactive under the three brakes until the Governor arms it.

7. **DOCUMENT AS SEEDS.**
   Every pass through the loop improves this file or files a lesson/review — the method compounds. What a project learns, the next project inherits.

## The test for any PM artifact

Same as every surface: name the real source it reads (reality-trace), attach evidence not claims, state the boundary of what it cannot see (for PoeTech: family-instance rows behind RLS), and leave the decision with the Governor.
