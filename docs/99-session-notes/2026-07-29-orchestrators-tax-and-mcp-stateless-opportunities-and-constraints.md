## What was brought

1. **"The Orchestrator's Tax"** — a single-incident case study: an orchestrating Claude Code session imported a background agent's full raw JSONL transcript (tens of thousands of tokens) to answer a throwaway status check, and the author's conclusion is that the scarce resource in multi-agent work is not tokens or wall-clock but **the orchestrator's working memory** — context pollution charges rent every turn after. His encoded fixes: small delegation waves; no transcript polling for status; no repo-wide git ops in concurrent agents; partition work by **cognitive locality** (shared mental model), not task count; subagents don't inherit skills — point them at files; and when encoding a lesson, **state the missing fact, not a decision procedure**.
2. **MCP 2026-07-28** — the largest protocol revision since launch. The official release post was later hand-carried whole (primary source, 2026-07-29), upgrading the earlier web-search verification: the protocol core is now **stateless** (the initialize handshake and `Mcp-Session-Id` retired — SEP-2575/2567; per-request `_meta` carrying version, identity, capabilities; optional `server/discover`), **Multi Round-Trip Requests** replace held-open streams for elicitation/sampling (SEP-2322 — `resultType: "input_required"`, client retries with `inputResponses`), routing moves to required `Mcp-Method`/`Mcp-Name` **headers** (SEP-2243), list results carry `ttlMs`/`cacheScope` **cache hints** with deterministic order (SEP-2549), **auth hardens** (RFC 9207 issuer validation; DCR formally deprecated toward CIMD; credentials issuer-bound), **Tasks** becomes a formal extension (poll-based `tasks/get`; `subscriptions/listen`), Roots/Sampling/Logging and the legacy HTTP+SSE transport are deprecated on a **twelve-month minimum window**, and all four Tier 1 SDKs — TypeScript, **Python**, Go, C# — speak it day-one. The spec's own state guidance: mint an explicit handle from a tool and let the model pass it back — visible state over transport-hidden sessions.

## Opportunities (routed, with dates)

- **The four new ground rules — adopted now (DR-0244, P36).** (1) Never import a raw subagent transcript to answer a status question; (2) delegate by cognitive locality — overlapping file/domain ownership between planned agents is a consolidation signal, not a cue to spawn more; (3) skills and context don't inherit — point spawned agents at the files to load, never paste inline; (4) a new standing rule states the missing FACT, not a decision procedure. These are teachable, checkable, and now on the ledger future sessions read first (LESSONS P36).
- **A sovereign MCP server became architecturally cheap — so it was BUILT the same day (DR-0236: nothing waits; brakes gate activation, never building).** Statelessness removed the exact objection (session affinity, SSE long-poll) that made an MCP server a poor fit for the DR-0132 lane, and the pre-existing direction was already on record (the 2026-06-02 "Agent-Native Surface Layer" research item). Shipped: `infra/nas-mcp/mcp_server.py` — a 2026-07-28-shape stateless endpoint (server/discover, cache-hinted tools/list, tools/call; bearer auth; Mcp-Method/Mcp-Name header-body agreement) over the NAS state the cloud sandbox can never reach: the dispatch reel, the Code Task snapshot, and a READ-ONLY view of the Cage's brakes. Proven live in the build sandbox (all methods + all refusal paths), pinned in CI (`nas-mcp-server.test.js` — including the v1-stays-read-only bright line), shipped INACTIVE with the ConnectBot activation runbook (`infra/nas-mcp/README.md`). Promotion to adopted = a real session reaching NAS state through it, measured useful. `re-review: 2026-08-25` (DR-0244).
- **The extensions framework as the standard-not-bespoke path.** When house tools ARE served to agents, extensions give a formal way to add house semantics (bearer auth posture, audit-event emission per call — the Cage's append-only ledger pattern) without forking the protocol. Rides the same re-review.
- **Two spec patterns are the house's Ways said back.** (1) The spec's explicit-handle guidance — *"mint an explicit handle from a tool and have the model pass it back… the model can see the handle"* — is SWIMLANES' law (state in durable visible places, never hidden in a session) adopted by the protocol itself. When the house serves MCP, these arrive free, already aligned. ## Constraints (held, with whys)

- **Recorded experience and house doctrine are senior; outside calibrations are heuristics.** The article's numeric thresholds (2–4 agents per wave; five as a consolidation signal) are one practitioner's calibration on one model and one codebase — the author says so himself, and his central cost ranking is the orchestrator grading its own mistake, unmeasured. Carried at DR-0100 tier 2: named heuristics, never law.
- **Built ≠ adopted (DR-0143 evidence rule).** Before this pass the house served NO MCP anywhere (verified: client-side consumption only). The server is now built, proven, and INACTIVE — staged, not adopted: promotion takes a measured result from real use here (a session actually reaching NAS state through it), never agreement with the ecosystem. Activation is the Governor's runbook hand; v1 is read-only by design, and any write tool is a separate DR-0089 governance gate with its own audit path.
- **The 2026-07-28 revision is breaking.** Old-spec and new-spec coexist through the formal twelve-month minimum window; nothing in the house's session-side MCP consumption is rewritten until the client side the house actually uses (including Claude) speaks the new revision in production. No migration work rides on this pass.
- **Subagent fan-outs stay under the existing brakes.** Cognitive-locality consolidation complements — never replaces — the three-brakes law for anything autonomous or timer-driven (DR-0225), the SWIMLANES shared-file serialization rule, and worktree isolation for genuine parallel writes. Context hygiene bounds what delegation carries; the brakes bound what delegation spends.
- **Layer 0 pruning is governance, not maintenance.** The hygiene opportunity above touches Darrell's recorded voice; it proceeds only as his reviewed decision (Tier C posture), never as an agent-side cleanup.

## Ways-review (DR-0108 questions, answered)

1. *Capability not used?* Three catches in one pass. The re-attach chain's first step (`ground.sh`) was documentation-only for six weeks; now it exists and runs. The house's context-economy doctrine was scattered (tool-routing doc, swimlanes, harness habit) rather than named rules — now DR-0244/P36. And the biggest: the agent first framed MCP-server activation as "the Governor's ConnectBot hand" — scoping to its own limits (the exact DR-0108 miss) — when the house's `services.json` self-deploy manifest already existed as the no-hands channel; corrected same-session on Darrell's "YOU DO IT": the service now self-deploys on merge, proven end-to-end in the sandbox (installer → venv → stamped token → the unit's exact ExecStart serving discover).
2. *Unverified "can't"?* "An MCP server doesn't fit the sovereign lane" was true under statefulness and is now false — the premise was re-verified against the new spec rather than carried stale; the honest current answer is "fits, not yet needed."
3. *Repeated friction absorbed?* Context compaction losing rules is the house's most-repeated failure class; P36 gives future sessions the named principle (subagents protect the orchestrator's memory) instead of each session rediscovering the economics.
4. *Scoped to my limits instead of the team's?* The MCP opportunity is scoped to the whole bench: it would serve ANY MCP-aware client the family runs — Claude sessions, the box agent, future sovereign models — not just the agent writing this.
5. *More streamlined way?* Fact-not-procedure rule encoding (DR-0244 §1.5) is itself the streamlining rule: it caps the bureaucracy each lesson is allowed to add.
